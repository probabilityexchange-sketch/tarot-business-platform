Merchandise checkout and paid-order handling — 2026-10-20

Approved prices: USD 34 shirts / USD 28 candles; quoted standard US shipping additional. Public payments remain disabled because the owner confirmed sales-tax setup is not yet completed. Stripe Tax settings are active but no active registrations were present. An appropriate registration/tax configuration must be reviewed before setting MERCH_TAX_REVIEWED=true and MERCH_CHECKOUT_ENABLED=true. Product tax codes: clothing/footwear 30011000 and general tangible goods 99999999; classification is part of launch review.

Customer: /shop/checkout loads only enabled, available Printify variants. No product costs or credentials are public. Address stays in component state, is not saved in browser storage and is sent only when requesting a quote. Quotes use server prices and actual Printify shipping, expire after 15 minutes and are protected by a random token hash. Checkout rechecks stock/shipping, creates an idempotent Stripe Customer with the quoted shipping destination, then an idempotent hosted Checkout Session. The customer cannot change the shipping address in Stripe; edits require a fresh quote on Kali's site. Automatic tax is enabled. Stripe sends its payment receipt. The shipping address is used solely for order fulfillment; no marketing signup occurs.

Stripe signed webhook and server-retrieved success-page fallback record only paid sessions with verified USD item/shipping/tax totals. Exactly one merch_orders document exists per Stripe session. Duplicate/concurrent notifications do not submit anything to Printify. Orders enter paid_awaiting_review. A second website action is required to transfer.

Owner: /admin/merch -> Refresh paid orders -> review items/address/payment -> confirm Printify's store approval is still Manual -> Send to Printify for manual approval. Server rechecks payment, refund/dispute state, availability and shipping cost before submission. There is no send_to_production call in this integration. Approve production separately in Printify only after reviewing its final production/fulfillment charges.

Transfer attempts are claimed in a Firestore transaction before provider access. external_id is kali-{Stripe session ID}. An ambiguous response becomes transfer_uncertain. Check Printify searches for that external ID without creating another order. Do not blindly retry or make duplicate manual orders. If the lookup finds nothing or an order is blocked by a refund, dispute, stock or shipping change, investigate the provider/Stripe records; this UI intentionally does not automatically retry or refund.

Scope: initial 100 newest owner orders; reconciliation searches up to 2000 Printify orders and stops for manual investigation beyond that. Refunds/cancellations and subsequent shipment tracking remain managed in Stripe/Printify, rather than automatically issued by this integration. Check Stripe before approving production; refunds after transfer require reviewing/canceling the corresponding Printify order manually.

Private collections merch_quotes/merch_orders have no client Firestore grants; server Admin SDK only. Quote documents contain deleteAfter (30 days); configure Firestore TTL on deleteAfter for abandoned quote retention. Do not set TTL on expiresAt because a legitimate Stripe payment can complete after quote expiry. Public success lookup exposes only payment/state flags, no buyer information. No real test purchase or Printify order has been created during development.

Before launch: review business tax setup and tax product classifications, samples and shop/return/shipping policies; complete a Stripe test-mode end-to-end purchase with test credentials and verify owner queue plus held Printify import in a controlled test. The server explicitly rejects transfers for test-mode payments, so a test Stripe payment cannot create a real Printify order. Use mocked Printify transport for test-mode end-to-end checks; any live held-order exercise needs separate controlled approval. Review the transfer record, then enable public checkout only when launch checks are complete.
